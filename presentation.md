---

# Зачем нужен WebGPU?

- JavaScript обычно выполняет вычисления на CPU.
- GPU содержит множество вычислительных блоков и может обрабатывать много независимых задач параллельно.
- WebGPU даёт веб-приложению современный интерфейс для графических и compute-вычислений.
- Пример задачи: обработать каждый пиксель изображения независимо от остальных.

---

# Что делает демонстрация?

1. Получает изображение: встроенное или загруженное пользователем.
2. Запускает выбранный алгоритм на CPU или GPU.
3. Сравнивает время на размерах 256×256, 512×512 и 1024×1024.
4. Повторяет измерения и берёт медиану.
5. Сравнивает массивы результатов CPU и GPU.
6. Показывает карту различий и график времени.

---

# Алгоритм 1: Box Blur

- Для каждого пикселя рассматривается квадратная область соседей.
- Красный, зелёный и синий каналы усредняются независимо.
- Радиус определяет размер области: `(2r + 1) × (2r + 1)`.
- Чем больше радиус, тем больше операций требуется для каждого пикселя.

---

# Алгоритм 2: Sobel

- Сначала RGB преобразуется в яркость.
- Два ядра Sobel оценивают горизонтальное и вертикальное изменение яркости.
- Модуль градиента показывает силу границы.
- Результат записывается как оттенок серого.

---

# Путь данных в WebGPU

1. `navigator.gpu.requestAdapter()` — запрос GPU adapter.
2. `adapter.requestDevice()` — получение GPU device.
3. Загрузка WGSL и создание compute pipeline.
4. Создание GPU buffers и bind group.
5. Запись входных данных и параметров.
6. Запуск compute pass.
7. Копирование результата в readback buffer.
8. `mapAsync()` — чтение результата JavaScript-кодом.

---

# WGSL и compute shader

- WGSL — язык шейдеров WebGPU.
- Функция `main` помечена `@compute`.
- `@builtin(global_invocation_id)` даёт координаты текущего invocation.
- Каждый invocation обрабатывает один пиксель.
- Проверка `x >= width` и `y >= height` защищает края изображения.

---

# Workgroups и параллелизм

- В проекте задано `@workgroup_size(8, 8, 1)`.
- Одна workgroup содержит до 64 invocations.
- `dispatchWorkgroups(ceil(width/8), ceil(height/8))` распределяет работу по изображению.
- GPU исполняет множество invocations параллельно, но реальная скорость зависит от оборудования и нагрузки.

---

# GPU buffers

- **Storage buffer:** массив входных или выходных пикселей.
- **Uniform buffer:** ширина, высота, номер алгоритма и радиус.
- **Readback buffer:** область, из которой JavaScript может прочитать результат.
- **Bind group:** связывает конкретные буферы с binding-слотами шейдера.

---

# Как измеряется производительность?

- Один прогревочный запуск.
- Несколько повторов (3, 5 или 7).
- Медиана времени вместо одного случайного измерения.
- Три размера изображения.
- Проверка максимальной и средней разницы между результатами.

**Границы измерения:** CPU — время алгоритма JavaScript; GPU — end-to-end от подготовки буферов и загрузки данных до readback. Это не чистое время исполнения GPU shader.

- Карта различий показывает абсолютное отличие RGB-каналов CPU и GPU; значения усилены для заметности.

---

# Почему GPU иногда медленнее?

- Для маленьких изображений вычислений может быть слишком мало.
- Создание буферов и передача данных требуют времени.
- Получение результата обратно в JavaScript добавляет задержку.
- CPU может эффективно выполнять простые циклы.
- Выигрыш GPU заметнее, когда много данных и промежуточные результаты остаются на GPU.

---

# Ограничения и обработка ошибок

- WebGPU требует совместимого браузера и безопасного контекста HTTPS/localhost.
- GPU adapter может быть недоступен.
- WGSL может содержать ошибки компиляции.
- Устройство может быть потеряно.
- Размер буфера ограничен возможностями адаптера.
- Поэтому приложение проверяет доступность API, компиляцию шейдера и лимит storage buffer.

# Что можно улучшить дальше?

- Добавить другие фильтры и настраиваемые ядра.
- Использовать GPU timestamp queries для измерения только GPU-команд, если функция доступна.
- Оставлять цепочки обработки на GPU, избегая лишнего readback.
- Исследовать оптимизации доступа к памяти и shared/workgroup memory.
