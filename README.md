# WebGPU Lab: обработка изображений и сравнение CPU/GPU

Учебный проект демонстрирует практическое применение WebGPU: обработку пиксельных данных на CPU и GPU, измерение производительности и проверку совпадения результатов.

## Возможности

- Box Blur — усреднение цветов пикселей в квадратной окрестности.
- Sobel — выделение границ по градиенту яркости.
- Обработка встроенного тестового изображения или загрузка собственного.
- Сравнение JavaScript CPU и WebGPU GPU на размерах 256×256, 512×512 и 1024×1024.
- Прогрев перед измерением и несколько повторов; в таблице выводится медиана.
- Проверка корректности CPU/GPU по максимальной и средней абсолютной разнице.
- Обработка отсутствия WebGPU, ошибок загрузки WGSL и потери GPU-устройства.

## Запуск

Требуется браузер с поддержкой WebGPU и локальный HTTP-сервер. Из корня проекта:

## Алгоритмы

### Box Blur

Для каждого пикселя берётся квадратная окрестность радиуса `r`. Красный, зелёный и синий каналы усредняются независимо:

`C_out(x,y) = sum(C_in(x+i,y+j)) / (2r+1)^2`

Координаты соседей за пределами изображения прижимаются к ближайшему краю. Альфа-канал результата равен 255.

### Sobel

Сначала вычисляется яркость пикселя:

`L = 0.299R + 0.587G + 0.114B`

Затем две матрицы Sobel приближённо находят горизонтальный и вертикальный градиенты `Gx` и `Gy`. Интенсивность границы равна `min(255, sqrt(Gx² + Gy²))`. Результат записывается в три цветовых канала.

## Как работает WebGPU

1. **Adapter и Device.** JavaScript запрашивает `GPUAdapter`, затем `GPUDevice` — интерфейс взаимодействия с GPU.
2. **WGSL module.** Текст шейдера загружается из `shaders/image.wgsl` и компилируется.
3. **Compute pipeline.** Pipeline описывает compute entry point `main` и layout ресурсов.
4. **GPU buffers.** Входные и выходные пиксели размещаются в storage buffers; размеры изображения, выбранный алгоритм и радиус передаются через uniform buffer.
5. **Bind group.** Связывает буферы с binding-слотами, объявленными в WGSL.
6. **Command encoder.** Создаёт compute pass и копирование результата в readback buffer.
7. **Workgroups.** Шейдер использует `@workgroup_size(8, 8, 1)`. Один invocation обрабатывает один пиксель. Число workgroups вычисляется как `ceil(width/8)` и `ceil(height/8)`. Проверка границ защищает неполные крайние группы.
8. **Readback.** После `mapAsync` JavaScript получает данные и рисует их на Canvas.

### Передача CPU ↔ GPU

Входные пиксели копируются из JavaScript в GPU storage buffer. GPU записывает результат в другой storage buffer. Затем команда `copyBufferToBuffer` переносит его в буфер с флагом `MAP_READ`, который JavaScript читает после завершения вычисления.

Чтение результата обратно необходимо для проверки и отображения на Canvas, но такая передача имеет стоимость. В производительном приложении часто выгодно оставить промежуточные результаты на GPU и передавать их в CPU только тогда, когда это действительно требуется.

## Методика benchmark

- Тестируются изображения 256×256, 512×512 и 1024×1024.
- Для каждого размера выполняется один прогревочный запуск CPU и GPU.
- Затем алгоритм повторяется указанное в интерфейсе число раз.
- Для сравнения используется медиана времени, чтобы единичные задержки меньше влияли на результат.
- CPU и GPU получают один и тот же набор пикселей и одинаковые параметры алгоритма.
- CPU измеряется по времени выполнения алгоритма в JavaScript.
- GPU измеряется end-to-end: создание буферов, загрузка входных данных, отправка команд, ожидание и readback результата.
- После повторов сравниваются массивы результатов.

**Важно:** CPU и GPU в таблице измеряются не в полностью одинаковых границах: CPU — только вычислительный цикл, GPU — полный путь от подготовки буферов и загрузки входа до получения результата обратно в JavaScript. Поэтому таблица показывает практическую стоимость использования GPU из браузера, а не чистое сравнение скорости процессоров. Чтобы измерить только GPU kernel, понадобились бы GPU timestamp queries (если они поддерживаются) или отдельная специализированная методика.

## Почему GPU не всегда быстрее

- Небольшие изображения содержат мало работы, и затраты на отправку команд могут оказаться больше экономии от параллелизма.
- Передача пикселей CPU → GPU и результата GPU → CPU требует времени.
- Для простых операций CPU может иметь очень эффективные оптимизированные циклы.
- На результат влияют GPU, драйвер, браузер, энергосберегающий режим и фоновые задачи.
- GPU лучше раскрывается на большом количестве независимых вычислений, особенно если промежуточные данные остаются в видеопамяти.

Не сравнивайте результаты разных компьютеров как абсолютный рейтинг. Повторите тест несколько раз и указывайте конфигурацию устройства и браузера.
