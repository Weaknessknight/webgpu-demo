# Практическая работа: меняем алгоритм WebGPU

Цель — показать, что ты понимаешь передачу данных, индексы invocation и работу compute shader, а не только умеешь запускать готовую страницу.

## Часть 1. Изменение алгоритма (обязательно)

1. Запусти приложение и выбери Box Blur.
2. Найди функцию `cpuFilter` в `app.js` и соответствующий блок `if (params.algorithm == 0u)` в `shaders/image.wgsl`.
3. Измени правило размытия: вместо квадрата радиуса 2 используй только крест из пяти пикселей (центр, сверху, снизу, слева, справа). Делитель должен быть равен 5.
4. Реализуй одинаковое изменение на CPU и GPU.
5. Запусти сравнение и проверь, что максимальная разница результатов остаётся небольшой.

## Часть 2. Контроль понимания

Ответь своими словами:

1. Почему `gid.x` и `gid.y` задают координаты пикселя?
2. Зачем нужна проверка `x >= width || y >= height`?
3. Чем storage buffer отличается от uniform buffer в этом проекте?
4. Почему перед чтением результата вызывается `mapAsync`?
5. Почему GPU может проиграть CPU на изображении небольшого размера?

## Часть 3. Мини-эксперимент

1. Проведи benchmark для Box Blur с радиусом 1 и 5.
2. Повтори тест для 256×256 и 1024×1024.
3. Заполни таблицу в отчёте:

| Размер | Радиус | CPU, мс | GPU end-to-end, мс | Кто быстрее? |
|---|---:|---:|---:|---|
| 256×256 | 1 | | | |
| 256×256 | 5 | | | |
| 1024×1024 | 1 | | | |
| 1024×1024 | 5 | | | |

4. Напиши 3–5 предложений о том, как изменились результаты и почему.

## Критерии выполнения

- Изменение реализовано и на JavaScript, и на WGSL.
- Результаты CPU/GPU проверены.
- Ученик может объяснить индексы, workgroups, буферы и readback.
- Таблица содержит собственные измерения, а не придуманные числа.
